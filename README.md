# 도서 대여 데이터베이스

SQLite로 회원, 도서, 분류, 대여 기록을 연결하고 SQL로 조회·집계·수정·삭제하는 실습입니다. 백엔드 프레임워크, View, 프로시저, 트리거는 사용하지 않습니다.

## 실행

Python 3.10 이상이면 됩니다. Python 기본 sqlite3를 사용하므로 별도 DB 서버 설치나 pip 설치가 필요 없습니다. VS Code 터미널에서 실행하세요.

```powershell
cd "D:\Desktop\서연이 숙제\2026\코디세이\codyssey-mission_B6-1"
python run.py
```

매번 새 샘플에서 시작합니다. 성공 시 이 폴더의 **실습용 library.db를 새 결과로 덮어씁니다.** 직접 수정한 DB를 보관하려면 실행 전에 다른 이름으로 복사하세요. SQL 오류가 나면 기존 DB 저장 전에 중단합니다.

실행 중 SQL과 결과가 터미널에 나오고, [results/query_results.txt](results/query_results.txt)에 저장됩니다. 결과 텍스트 제출이 허용되므로 쿼리마다 별도 스크린샷을 만들 필요는 없습니다.

## 파일 역할

| 파일 | 역할 |
| --- | --- |
| schema.sql | 테이블·PK·FK·제약조건 생성 |
| seed.sql | 부모부터 순서대로 샘플 INSERT |
| queries.sql | 번호와 설명을 붙인 핵심 SQL 15개 |
| run.py | SQL 실행, 제약조건 확인, 결과 및 DB 저장 |
| results/query_results.txt | 실제 실행 결과. SQL 15개와 수정/삭제 전후 포함 |

Python은 실행 도우미입니다. 데이터 설계와 처리의 중심은 SQL 파일입니다. queries.sql의 `-- Q01:` 같은 주석은 실행 도우미가 쿼리를 구분하는 기준이므로 유지하세요.

## 테이블과 관계

| 테이블 | 역할 | 처음 입력하는 행 수 |
| --- | --- | --- |
| category | 분류 이름을 한 곳에서 관리 | 10 |
| book | 도서 제목·가격·분류 ID | 12 |
| member | 회원 이름·이메일 | 12 |
| rental | 누가 어떤 책을 언제 빌렸는지 | 16 |

```text
category (1) ── (N) book
member   (1) ── (N) rental
book     (1) ── (N) rental
```

회원 1명은 여러 번 빌릴 수 있습니다. 대여 기록에 회원 이름을 반복 저장하는 대신 member_id를 저장합니다. 회원 정보를 수정할 때 member 한 곳만 바꾸면 됩니다. 분류와 도서도 같은 이유로 분리했습니다.

PK는 각 행을 구분하는 ID이고, FK는 다른 테이블의 PK를 참조합니다. book.category_id, rental.member_id, rental.book_id가 FK입니다. 참조 대상에 UNIQUE를 걸지 않았으므로 하나의 부모를 여러 자식 행이 참조할 수 있습니다. 같은 이름의 회원도 서로 다른 ID로 구분합니다.

ID와 원 단위 가격은 INTEGER, 이름·이메일·제목은 TEXT입니다. 날짜는 SQLite에 독립된 DATE 저장 타입이 없으므로 `YYYY-MM-DD` 형식의 TEXT로 저장합니다. 고정 형식에서는 문자열 정렬이 날짜 순서와 같습니다. 이 실습은 완전한 날짜 입력 검증을 구현하지 않습니다. returned_at의 NULL은 미반납을 뜻합니다.

필수 값은 NOT NULL, 분류명과 회원 이메일은 UNIQUE, 양수 가격과 반납일 순서는 CHECK로 제한합니다. SQLite는 **접속할 때마다 PRAGMA foreign_keys = ON**이 필요합니다. 다른 도구로 DB를 열어 수정할 때도 먼저 활성화하세요.

## SQL 15개

| 번호 | 범주 | 확인하는 내용 |
| --- | --- | --- |
| Q01~Q04 | 기본 조회 4개 | 가격 조건, 가격순 TOP 3, 제목 검색, 미반납 목록 |
| Q05~Q08 | 조인 4개 | 도서·분류, 회원·대여, 미반납 상세, 대여 없는 회원 포함 |
| Q09~Q11 | 집계 3개 | 회원별 COUNT, 분류별 COUNT/SUM, 분류별 AVG |
| Q12 | 서브쿼리 1개 | 전체 평균보다 비싼 도서 |
| Q13 | UPDATE | 12번 대여 반납 처리 |
| Q14 | DELETE | 16번 대여 삭제 |
| Q15 | CREATE INDEX | 회원 ID로 대여 기록 찾기 |

UPDATE/DELETE의 전후 SELECT와 인덱스 확인 SELECT/EXPLAIN은 결과 검증용으로 실행 도우미가 추가합니다. 필수 15개 SQL은 queries.sql에 있습니다. DELETE 후에도 rental은 15행이 남습니다.

## 결과로 설명하기

**INNER JOIN과 LEFT JOIN:** Q06은 대여 기록이 있는 회원만 보여 줍니다. Q08은 모든 회원을 유지하므로 대여가 없는 11, 12번 회원도 rental_id=NULL로 나옵니다. 회원 한 명이 여러 번 빌리면 결과에도 여러 행이 생깁니다.

**GROUP BY와 집계:** Q09는 회원 ID/이름으로 묶고 COUNT(r.id)로 기록 수를 셉니다. COUNT(*)를 쓰면 대여가 없는 회원의 LEFT JOIN 결과 행까지 1로 셀 수 있으므로 피했습니다. Q10의 SUM은 도서 가격 합계이며 대여 매출이 아닙니다. Q11은 분류별 가격 평균입니다.

**인덱스:** rental.member_id로 회원별 대여를 반복 조회하므로 이 컬럼에 인덱스를 만들었습니다. Q15 실행 결과의 EXPLAIN QUERY PLAN에서 인덱스 사용 여부를 확인합니다. 16행에서 큰 속도 차이를 주장할 수는 없습니다. 인덱스는 저장 공간과 쓰기 비용도 추가합니다.

**상대적으로 복잡한 Q09의 순서:** 모든 회원을 기준으로 LEFT JOIN → 회원별 그룹 생성 → NULL이 아닌 대여 ID 개수 계산 → 대여 횟수 내림차순 정렬. 대여하지 않은 회원을 포함하면서 0으로 계산하는 부분이 핵심입니다.

**무결성 실습:** 실행 도우미가 없는 회원/분류를 참조하는 INSERT, NULL 제목, 중복 이메일을 실제로 시도합니다. 오류로 막힌 결과를 기록하고 SAVEPOINT로 되돌립니다. 해결은 부모를 먼저 등록하거나 존재하는 부모 ID를 사용하는 것입니다. 제약을 끄는 방식으로 해결하지 않습니다.

엑셀에서도 데이터를 연결할 수 있지만 관계형 DB는 PK/FK/제약조건을 정의해 연결과 저장 규칙을 DB에서 검사합니다. SQL JOIN과 GROUP BY로 반복 가능한 조회를 작성할 수 있습니다. 실습 중 어려웠던 점은 본인이 직접 실행하며 확인한 경험을 바탕으로 설명하세요.

DB 파일은 실행으로 재생성할 수 있어 Git에서 제외합니다. SQL과 실행 도우미, 문서, 결과 텍스트를 제출하면 됩니다.
